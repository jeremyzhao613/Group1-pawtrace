# PawTrace Feature Prioritization

This page is the web-readable version of the uploaded MoSCoW PDF:
[pawtrace-moscow-prioritization.pdf](pawtrace-moscow-prioritization.pdf).

## Priority Summary

| Priority | Product meaning |
| --- | --- |
| Must have | Required for the first working PawTrace prototype and the core lost-pet safety flow. |
| Should have | Important for product quality and daily care, but not as launch-blocking as GPS and NFC. |
| Could have | Useful bonus features if time allows. |
| Won't have this semester | Out of scope for the current semester version. |

## Must Have

| Feature | Reason |
| --- | --- |
| Real-time GPS location | Without location tracking, the product cannot solve the main problem of helping owners find lost pets. |
| Electronic fence / safe-area alert | Key for loss prevention. If the pet leaves the safe zone, the owner must receive an alert. |
| NFC pet identity card | If someone finds the pet, they need a fast way to see the pet's information and contact the owner. |
| Basic mobile app map page | Owners need a simple app interface to check location, set safe zones, and receive alerts. |
| Pet profile and owner contact information | Supports both the app and NFC rescue flow. Without it, the finder cannot contact the owner. |

## Should Have

| Feature | Reason |
| --- | --- |
| Health monitoring: heart rate, body temperature, activity level | Important for daily pet care, but the product can still be demonstrated with location and identity features first. |
| Health dashboard in the app | Users should be able to understand health data clearly, but it is not as launch-blocking as GPS and NFC. |
| Movement history | Useful for understanding pet behavior and past routes, but real-time location is more important. |
| Clear push notifications | Alerts are important, but the first demo can still show alert logic even if notification design is basic. |

## Could Have

| Feature | Reason |
| --- | --- |
| AI-assisted health photo check | Useful bonus feature, but not the core of the product's safety function. |
| Vaccination record display | Helpful for pet identity and health records, but not essential for the first working prototype. |
| Pet traits/personality description | Helps finders understand the pet, but it is not required for the main rescue flow. |

## Won't Have This Semester

| Feature | Reason |
| --- | --- |
| Support for campus stray animal management system | Possible future direction, but the first focus is household pet owners. |
| Social features for pet owners | Pet socialization is not part of the core safety and health problem. |
| Advanced multi-pet organization platform | Useful later, but too large for the current semester scope. |
